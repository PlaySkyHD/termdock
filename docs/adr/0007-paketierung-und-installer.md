# ADR 0007: Paketierung und Installer

Status: angenommen (19.11.2026), ergänzt um Auto-Update und Release (24.11.2026, #136)

## Kontext

Phase 4 des Konzepts (Kapitel 12) verlangt eine App, die sich ohne Repo und ohne Node installieren lässt. Der Core ist ein eigener Prozess, den Electron als Node startet (ADR 0001); node-pty bringt N-API-Prebuilds mit, SQLite ist `node:sqlite`. Nutzerentscheidung vom 19.11.2026 (#131): NSIS-Installer pro Benutzer, ohne Adminrechte, unsigniert. Auto-Update ist #136.

## Entscheidung

- **Werkzeug:** `electron-builder` (devDependency von `apps/desktop`, gepinnt), Konfiguration in `apps/desktop/electron-builder.json`, Bau mit `npm run dist -w apps/desktop` nach `apps/desktop/release/` (`TermDock-Setup-<version>.exe`, entpackt `win-unpacked`). Electron kommt aus `node_modules/electron/dist`, also dieselbe Version wie bei `npm start`. Publish-Ziel GitHub `PlaySkyHD/termdock` mit `releaseType: draft` (seit #136), damit der Bau `latest.yml`, `TermDock-Setup-<version>.exe.blockmap` und im Paket `resources/app-update.yml` erzeugt; `dist` bleibt `--publish never`, lädt also nichts hoch und braucht keinen Token. Kein Zertifikat.
- **Installer:** NSIS mit Assistent (`oneClick: false`), nur für den aktuellen Benutzer (`perMachine: false`, `allowElevation: false`, Makro `customInstallMode` in `resources/installer.nsh` überspringt die Auswahl „für alle Benutzer“), Ziel `%LOCALAPPDATA%\Programs\TermDock`, deutsche Oberfläche, Startmenü- und Desktop-Verknüpfung, Deinstallation über „Apps“. Die Willkommensseiten nennen Zielordner, Datenordner, dass ein laufendes TermDock samt Core beendet wird und dass laufende WSL-Sessions dabei weiterlaufen (#140).
- **Identität:** `appId` `io.github.playskyhd.termdock`, `productName` TermDock. Das Icon `resources/icon.ico` (16–256 px) erzeugt `npm run icon -w apps/desktop` (`scripts/make-icon.mjs`, Electron zeichnet `assets/icon.svg`); es ist eingecheckt, weil der Buchstabe die Systemschrift nutzt.
- **Daten:** Der Datenordner bleibt `%APPDATA%\TermDock`; die Deinstallation lässt ihn stehen (`deleteAppDataOnUninstall: false`). Das Electron-Profil (`userData`) setzt der Main ausdrücklich auf `%APPDATA%\@termdock\desktop` (`appUserDataDir`), im Repo und im Paket gleich, unabhängig vom npm-Namen. Damit teilen Repo-App und installierte App die Einzelinstanz-Sperre: Nie laufen zwei Mains auf einem Core. Im Paket setzt der Main die AppUserModelID `io.github.playskyhd.termdock` (= `appId`), sonst zeigt die Taskleiste zwei Symbole.
- **Paketinhalt:** `dist/main`, `dist/preload`, `dist/shared`, `dist/renderer` ohne Tests; React und xterm.js nur gebündelt im Renderer. `@termdock/core`, `@termdock/protocol` und `node-pty` liegen per `asarUnpack` in `resources/app.asar.unpacked`. Kein Rebuild nativer Module (`npmRebuild: false`): node-pty lädt seine N-API-Prebuilds unter der Electron-ABI.
- **Core im Paket:** `coreEntryPath({ packaged, resourcesPath })` liefert im Paket `resources/app.asar.unpacked/node_modules/@termdock/core/dist/bin/termdock-core.js`, sonst wie bisher `packages/core/dist/bin/termdock-core.js`. Der Core läuft weiter als `process.execPath` (`TermDock.exe`) mit `ELECTRON_RUN_AS_NODE=1` (ADR 0001), ganz außerhalb von `app.asar`.
- **Prüfmodus `--smoke-test`:** ohne Fenster, nach dem Vorbild des Screenshot-Modus (ADR 0006): eigene Pipe, eigener tmux-Socket, Electron-Profil unter `TERMDOCK_DATA_DIR`, keine Einzelinstanz-Sperre. Die App startet den Core, wartet auf `hello` und `core.status` (höchstens 90 s, ein danach noch startender Core wird bis zu 15 s abgewartet), beendet ihn mit `core.shutdown { stopSessions: true }` (sonst Kill) und endet mit 0; Fehler ergeben 1. Fehlendes `TERMDOCK_DATA_DIR`, `%APPDATA%\TermDock` oder ein Ordner darin (ein zweiter Core auf der produktiven Datenbank würde deren Sessions gegen den leeren tmux-Socket der Prüfung abgleichen) oder `--screenshot` daneben ergeben 2.
- **CI:** Job `package` auf `windows-latest`: `npm ci`, `npm run dist -w apps/desktop`, Prüfung von `latest.yml`, `.blockmap` und `app-update.yml` (#136), Laden von `conpty.node` und `pty.node` mit dem gepackten Electron, `TermDock.exe --smoke-test` mit `TERMDOCK_DATA_DIR` unter `runner.temp`, Upload des Installers als Artefakt `TermDock-Setup` (7 Tage). Ohne WSL meldet der Core `wsl` als nicht verfügbar; das ist erwartet.

- **Release (#136):** `.github/workflows/release.yml` läuft nur bei Push eines Tags `v*`. Er prüft, dass der Tag `v<version>` aus `apps/desktop/package.json` ist (sonst Abbruch vor dem Bau), baut wie der Job `package`, führt den Prüfmodus aus und legt mit `gh release create --draft --verify-tag` ein Draft-Release mit Installer, `.blockmap` und `latest.yml` an. Rechte: oben `contents: read`, im Job `contents: write`; nur `GITHUB_TOKEN`, und den sieht nur dieser letzte Schritt (electron-builder lädt nichts hoch). Actions mit Commit-SHA wie in `ci.yml`. Veröffentlichen ist Handarbeit des Nutzers: Version per PR erhöhen, Tag auf `main` pushen, Draft prüfen, „Publish release“.
- **Auto-Update (#136):** `electron-updater` 6.8.11 (Dependency von `apps/desktop`) nur in der gepackten App im normalen Start, nicht im Screenshot- oder Prüfmodus und nicht aus dem Repo (`updateChecksAllowed`). 30 s nach dem Start, dann alle 4 Stunden, jeweils nur wenn die Einstellung `checkForUpdates` nicht `false` ist (Protokoll 1.7, Dialog „Allgemein“); antwortet der Core nicht, fällt die Suche aus. electron-updater wird erst bei der ersten Suche geladen (`lazyUpdater`), nicht vor den Fenstern. Download im Hintergrund (`autoDownload`), kein Install beim Beenden (`autoInstallOnAppQuit: false`: ein normales Beenden behält den Core samt Windows-Shells), keine Vorabversionen. Fehler gehen nur nach `desktop.log` (Quelle `updater`). Ein geladenes Update zeigt jedes Fenster unten rechts als nicht-modalen Dialog „Jetzt neu starten / Später“ (ADR 0006); „Später“ gilt für alle Fenster bis zum nächsten Start. „Jetzt neu starten“ (`QuitFlow.installUpdate`): Fenster im Layout behalten, Supervisor auf `stopped`, Layout speichern, `core.shutdown { stopSessions: false }` (tmux-Sessions und WSL-Keepalive bleiben, Windows-Shells enden, ADR 0001), Verbindung schließen, dann `quitAndInstall(true, true)` und `app.quit()` (auch wenn der Installer nicht startet, bleibt kein Fenster ohne Core zurück): Installer still (`--updated /S --force-run`; er wartet auf das Ende der Prozesse unter `$INSTDIR` und beendet übrige), danach startet die neue Version, ihr Core gleicht ab und bindet die tmux-Sessions an (ADR 0005). Logik ohne Electron in `update-service.ts` und `shared/update-decision.ts`, electron-updater nur in `electron-updater-port.ts`.
- **Unsigniert (Nutzerentscheidung 24.11.2026):** Kein Zertifikat, keine Signing-Secrets. `app-update.yml` hat keinen `publisherName`, also prüft electron-updater keine Signatur, nur die SHA-512 aus `latest.yml` (HTTPS zu GitHub). SmartScreen warnt beim ersten Installieren; ein stilles Update fragt nicht erneut. **Risiko:** Wer das Konto `PlaySkyHD` oder die Releases übernimmt, kann installierten Apps ein beliebiges Programm als Update geben; `latest.yml` und Installer liegen am selben Ort, die Prüfsumme schützt also nur vor kaputten Downloads, nicht vor einem Angreifer. Begrenzt wird das durch Drafts mit manuellem Veröffentlichen (ein Fehler im Workflow erreicht niemanden) und 2FA des Kontos, nicht beseitigt. Eine Signatur ist eine eigene Entscheidung.

## Abnahme (manuell, mit dem Nutzer)

1. Repo-App (alle Fenster) und Repo-Core beenden (`docs/agent-lessons-learned.md`, Abschnitt 1). Sonst übergibt die installierte App an den laufenden Repo-Main (gemeinsame Einzelinstanz-Sperre) oder verbindet sich mit dem Repo-Core (gleiche Pipe).
2. `TermDock-Setup-<version>.exe` aus dem CI-Artefakt oder `apps/desktop/release/` ausführen (SmartScreen: „Weitere Informationen“, „Trotzdem ausführen“). Es kommt keine UAC-Abfrage und keine Auswahl „für alle Benutzer“.
3. Startmenü-Eintrag „TermDock“ starten, eine WSL-Session anlegen und darin tippen. Die Taskleiste zeigt ein TermDock-Symbol.
4. TermDock beenden, über „Einstellungen → Apps“ deinstallieren. `%LOCALAPPDATA%\Programs\TermDock` ist weg, `%APPDATA%\TermDock\termdock.db` ist noch da.
5. Update von Version A auf B mit laufender tmux-Session (#136): Version A aus einem veröffentlichten Release installieren, eine WSL-Session mit `while :; do date +%T; sleep 1; done` und eine Windows-Shell starten, `wsl.exe -d Ubuntu --exec tmux -L termdock list-panes -a -F '#{session_name} #{pane_pid}'` notieren. Version B (höher) per Tag bauen lassen und das Draft veröffentlichen. In A höchstens 30 s nach dem Start (oder nach 4 Stunden) erscheint unten rechts „Update auf Version B ist bereit.“ mit dem Satz, dass die Windows-Shell endet; das Terminal behält beim Erscheinen die Eingabe. „Jetzt neu starten“ klicken. Erwartet: ohne SmartScreen- und UAC-Abfrage startet B (Eigenschaften → Details von `%LOCALAPPDATA%\Programs\TermDock\TermDock.exe` nennen Version B), die WSL-Session zeigt weiter laufende Uhrzeiten, `list-panes` nennt dieselbe PID, die Windows-Shell ist „Unterbrochen“. Mit „Später“ statt dessen: Der Dialog verschwindet in allen Fenstern, Beenden installiert nichts, der nächste Start bietet B wieder an.

## Folgen

- Ein Update oder eine Deinstallation beendet laufende `TermDock.exe`-Prozesse nach Rückfrage, auch den Core im Hintergrund, und zwar ohne `core.shutdown`. Der WSL-Keepalive läuft losgelöst vom Core und liegt nicht unter `$INSTDIR` (`wsl.exe` in `System32`); er überlebt das Update und hält die Distro samt tmux-Sessions wach (ADR 0003, #140). Der nächste Start gleicht ab (ADR 0005), bindet die Sessions wieder an und übernimmt den Keepalive.
- Ohne Signatur warnt SmartScreen beim ersten Installieren. Signatur, Store, MSI und ARM64 sind nicht Teil dieser Entscheidung.
- Ein Auto-Update beendet den Core vorher selbst mit `core.shutdown { stopSessions: false }`; der Installer findet dann kein laufendes `TermDock.exe` mehr (sonst beendet er es wie oben). Windows-Shells überleben ein Update nicht, der Dialog sagt das.
- Der Bau lädt NSIS und 7-Zip aus den GitHub-Releases von electron-builder.
